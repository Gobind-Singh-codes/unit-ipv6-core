## 2. Design notes

- **Probes are fragmented in userspace** (`fragment6` at interface MTU): IPv6
  senders size to the path themselves, and the kernel refuses oversize `sendp`
  with EMSGSIZE (first observed as a bare ERROR before this fix). Frag counts
  are recorded (`baseline_probe_frags`, `post_probe_frags`, `iface_mtu`).
- **Small replies carry no PMTU information.** An earlier revision failed a DUT
  for 69-byte replies "looking reduced" — a false FAIL, removed. Only
  first-fragment payloads (implied wire MTU) or the cache readout can move the
  verdict; anything else is INCONCLUSIVE.
- **Strict cache mode** (`--pmtu-require-cache`) fails closed unless the readout
  comes from a real route-cache entry (the word `cache` in output). On this
  DUT's quiet path no cache entries exist, so strict mode reports
  ERROR/INCONCLUSIVE by design — the standard legs above are the verdicts.
- A baseline (pre-PTB) state is load-bearing, not optional: the ER forbids both
  *applying* the PTB and *dropping below* 1280, and only before/after comparison
  tests the first half. The PTB quotes a real DUT packet because stateful stacks
  ignore PTBs referencing unknown flows.
